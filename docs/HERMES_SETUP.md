# Hermes setup (Linux host)

Plan B supervisor runs on the **same Linux host** as Docker, not inside the n8n container.

## Install

```bash
curl -fsSL https://raw.githubusercontent.com/NousResearch/hermes-agent/main/scripts/install.sh | bash
hermes setup
```

## Project context

```bash
cd ~/Auto_media   # WSL ext4 path, not /mnt/c/...
amctl apply
hermes   # uses config/hermes/CONTEXT.md
```

## MCP

`config/hermes/mcp.json` is generated by `amctl apply` when `publish.mode` is `auto` or `dom`.

Keep `features.hermes_gateway: false` to avoid Telegram conflicts with n8n HITL.

## Circuit breaker flow

1. n8n Meta API fails 3 times → `data/logs/api_dead.json`（由 `write_circuit_breaker.sh` 寫入）。
2. Host checks signal:

```bash
./scripts/check_api_dead.sh
# exit 2 = signal present
```

3. Plan B（手動或自動）：

```bash
# 手動啟動 Hermes 處理
./scripts/hermes-plan-b.sh

# 或讓 check 腳本自動呼叫
AUTO_MEDIA_HERMES_AUTO=1 ./scripts/check_api_dead.sh

# 透過 amctl
amctl supervisor
```

## Cron (no-agent poll)

```bash
hermes cron create "every 1m" \
  "cd /path/to/Auto_media && ./scripts/check_api_dead.sh" \
  --workdir /path/to/Auto_media
```

When `check_api_dead.sh` exits 2, wire your cron wrapper to run `hermes-plan-b.sh`.
