# Hermes setup (Linux host)

Plan B supervisor runs on the **same Linux host** as Docker, not inside the n8n container.

## Install

```bash
curl -fsSL https://raw.githubusercontent.com/NousResearch/hermes-agent/main/scripts/install.sh | bash
hermes setup
```

## Project context

```bash
cd ~/Auto_media   # WSL ext4 path, not /mnt/c/...
amctl apply
hermes   # uses config/hermes/CONTEXT.md
```

## MCP

`config/hermes/mcp.json` is generated by `amctl apply` when `publish.mode` is `auto` or `dom`.

## B-prime Telegram Gateway (Model A)

Set `features.hermes_gateway: true` in `config/platform.yaml`, then `amctl apply`.

- **Gateway** (`scripts/hermes_telegram_gateway.py`): sole Telegram webhook; enqueue + HTTP 200; worker handles I/O.
- **n8n**: state machine (Wait, revise, publish). Preview via `POST /internal/schedule-prereview` after `Save wait resume URL`.
- **Dev (no HTTPS)**: `GATEWAY_URL=http://localhost:8787 bash scripts/start_gateway.sh` and `bash scripts/telegram_poll_forwarder.sh` (poll targets Gateway `/telegram`).
- **Production**: `bash scripts/enforce_telegram_gateway.sh` after `verify_n8n_node_disable.sh` passes on n8n 2.21.7.
- **Abort**: `abort_mode: pre_wait` (DELETE execution, never resume) vs `post_wait` (resume reject when already waiting).
- Do **not** enable n8n `Telegram Trigger` while Gateway is active.

## Circuit breaker flow

1. n8n Meta API fails 3 times → `data/logs/api_dead.json`（由 `write_circuit_breaker.sh` 寫入）。
2. Host checks signal:

```bash
./scripts/check_api_dead.sh
# exit 2 = signal present
```

3. Plan B（手動或自動）：

```bash
# 手動啟動 Hermes 處理
./scripts/hermes-plan-b.sh

# 或讓 check 腳本自動呼叫
AUTO_MEDIA_HERMES_AUTO=1 ./scripts/check_api_dead.sh

# 透過 amctl
amctl supervisor
```

## Cron (no-agent poll)

```bash
hermes cron create "every 1m" \
  "cd /path/to/Auto_media && ./scripts/check_api_dead.sh" \
  --workdir /path/to/Auto_media
```

When `check_api_dead.sh` exits 2, wire your cron wrapper to run `hermes-plan-b.sh`.
